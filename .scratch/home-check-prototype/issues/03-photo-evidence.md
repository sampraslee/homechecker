# 03: Photo Evidence

**What to build:** On an Item, the Inspector takes photos in the app. Each photo is saved immediately with three versions — untouched original, Evidence copy (~1920–2048 px longest edge, JPEG ~80–85%) and thumbnail — and thumbnails show on the Item. Introduces the Image processor adapter. See the spec: Evidence, Image processor adapter.

**Blocked by:** 02

**Status:** ready-for-agent

- [x] Capture a photo from an Item (camera via file input with capture or getUserMedia)
- [x] Original is stored unchanged and never overwritten; Evidence copy and thumbnail are generated by the Image processor adapter
- [x] Photo is persisted before the UI confirms capture; survives app close and reopen
- [x] Item shows photo thumbnails; tapping opens the full image
- [x] Delete a photo (the "only while Draft" check is deferred to 06)
- [x] Evidence belongs to exactly one Item
- [x] Core tests (stubbed Image processor) cover capture, persistence of all three versions and deletion (Draft-only deletion is tested in 06)

## Comments

- `removeItem` (from 02) currently deletes the Item outright. Once Items can hold Evidence, decide whether removing an Item with Evidence is refused (like `area-has-items`) or cascades. The brief says originals are never deleted by the app, which points to refusing.
- Decided: removing an Item that has Evidence is refused (`item-has-evidence`). Deleting a photo is the Inspector's own choice (story 34), so it removes the original too. The "never deleted by the app" rule is about the app acting on its own.
- The original is saved before processing. If the Image processor fails, the photo is kept unprocessed, and `finishPhotoProcessing()` (run at app start) retries it later.
