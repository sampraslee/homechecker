# 03: Photo Evidence

**What to build:** On an Item, the Inspector takes photos in the app. Each photo is saved immediately with three versions — untouched original, Evidence copy (~1920–2048 px longest edge, JPEG ~80–85%) and thumbnail — and thumbnails show on the Item. Introduces the Image processor adapter. See the spec: Evidence, Image processor adapter.

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] Capture a photo from an Item (camera via file input with capture or getUserMedia)
- [ ] Original is stored unchanged and never overwritten; Evidence copy and thumbnail are generated by the Image processor adapter
- [ ] Photo is persisted before the UI confirms capture; survives app close and reopen
- [ ] Item shows photo thumbnails; tapping opens the full image
- [ ] Delete a photo only while the Inspection is Draft
- [ ] Evidence belongs to exactly one Item
- [ ] Core tests (stubbed Image processor) cover capture, persistence of all three versions and Draft-only deletion

## Comments

- `removeItem` (from 02) currently deletes the Item outright. Once Items can hold Evidence, decide whether removing an Item with Evidence is refused (like `area-has-items`) or cascades. The brief says originals are never deleted by the app, which points to refusing.
